# Aquarium Ecosystem Simulator

Учебный проект по дисциплине «Распределённые системы» (Term 3, 2026–2027):
7 лабораторных работ по паттернам проектирования GoF, реализуемых на одном
общем, постепенно растущем 2D-приложении «аквариум». Каждая лаба добавляет
1–2 паттерна поверх кода предыдущих лаб, не ломая уже реализованный функционал.

## Стек

- C++17
- SFML 3 (Graphics/Window/System)
- CMake 3.20+
- macOS + VS Code (C/C++, CMake Tools)

## Сборка и запуск

```bash
mkdir -p build && cd build
cmake ..
cmake --build .
./Aquarium
```

## Управление

| Клавиша | Действие |
|---|---|
| `B` | Переключить биом (Freshwater → Reef → DeepSea → по кругу) |
| `Space` | Заспавнить рыбу |
| `F` | Заспавнить еду |
| `W` | Заспавнить водоросль |
| `D` | Заспавнить декорацию (камень/ракушка) |
| `S` | Заспавнить стаю из 5 рыб рядом со случайной точкой |
| `E` | Переключить формат отчёта (HTML → TXT → XML → по кругу) |
| `R` | Экспортировать отчёт о состоянии аквариума в `Reports/` |
| `Z` | Отменить последнее действие (undo) |
| `X` | Повторить отменённое действие (redo) |
| `P` | Применить пресет обустройства (2 водоросли + 2 декорации одной командой) |
| `U` | Feeding frenzy — заспавнить 10 еды одной командой |
| `Esc` | Закрыть приложение |

Полный список управления также отображается на экране (полупрозрачная панель
в левом верхнем углу). Окно можно свободно менять в размерах — все обитатели
пропорционально пересчитывают позиции под новый размер.

## Статус

### Лаба 1 — Abstract Factory ✅

`AquariumFactory` — абстрактная фабрика с методами `MakeFish`, `MakeFood`,
`MakeWeed`, `MakeDecoration`. Три конкретных семейства (биома):
`FreshwaterFactory`, `ReefFactory`, `DeepSeaFactory` — переключаются в
рантайме без пересборки (клавиша `B`). Четыре иерархии абстрактных продуктов:
`Fish`, `Food`, `Weed`, `Decoration`.

### Лаба 2 — Prototype + Singleton ✅

Каждая конкретная фабрика (`FreshwaterFactory`/`ReefFactory`/`DeepSeaFactory`)
теперь синглтон (`GetInstance()`, приватный конструктор). Внутри себя хранит
карту прототипов по видам рыб + по одному прототипу еды/водоросли/декорации,
заполняемую один раз при первом обращении. `MakeFish`/`MakeFood`/`MakeWeed`/
`MakeDecoration` больше не вызывают `new` — клонируют готовый прототип через
виртуальный `Clone(position)`, добавленный во все продукты.

### Лаба 3 — Builder + Factory Method ✅

Отчёт о состоянии аквариума собирается по шагам через `IReportBuilder`
(`BuildHeader`/`BuildBody`/`BuildFooter`/`GetResult`), которые вызывает
`ReportDirector` в фиксированном порядке. Три конкретных строителя —
`HtmlReportBuilder`, `TxtReportBuilder`, `XmlReportBuilder`. Выбор нужного
строителя по формату, выбранному пользователем (клавиша `E`), — через
`ReportBuilderCreator` (Factory Method) и три конкретных создателя.
Готовый отчёт (клавиша `R`) сохраняется в `Reports/` с меткой времени
в имени файла.

### Лаба 4 — Adapter ✅

`StackAdapter`/`QueueAdapter` — шаблонные обёртки, сужающие широкий интерфейс
`std::vector`/`std::list` до строгого `Push`/`Pop` (LIFO/FIFO). Используются не
изолированно, а в двух реальных фичах: `ActionHistory` (журнал последних
действий пользователя на `StackAdapter`, отображается в HUD, фундамент под
будущий undo-стек Лабы 7) и `ExportedReportsLog` (хронологический список
отчётов, экспортированных за сессию, на `QueueAdapter`, попадает отдельной
секцией в сам отчёт).

### Лаба 5 — Composite ✅

`AquaticEntity` — общий интерфейс (`Update`/`Draw`/`RescalePosition`/
`CollectFishInfo`), который реализуют и одиночная `Fish` (лист), и `Shoal`
(стая, композит) — хранит внутри несколько `AquaticEntity` и просто
пересылает каждый вызов всем участникам. `Scene` работает с обоими
одинаково, через один и тот же список `entities_`, не различая, стая
перед ней или одна рыба. Клавиша `S` — заспавнить стаю из 5 рыб.

### Лаба 6 — Chain of Responsibility ✅

Каждый кадр рыба решает, куда плыть, через цепочку обработчиков
(`FishDecisionHandler`): `WeedHidingHandler` (хищник рядом и есть
водоросль — плыть прятаться) → `PredatorNearbyHandler` (хищник рядом —
убегать) → `FoodNearbyHandler` (еда рядом — плыть к ней) →
`FlockingHandler` (иначе — три правила буидов: сближение/выравнивание/
разбегание с рыбами того же вида и биома; обработчик по умолчанию,
всегда срабатывает, если раньше не сработало). `Fish::Update` теперь
общий для всех биомов — конкретные рыбы больше не задают направление
движения сами, только визуал (`Draw`).

### Лаба 7 — Command ✅

`ICommand` (`Execute`/`Undo`) — общий интерфейс команды. Конкретные команды
оборачивают каждое пользовательское действие, которое имеет смысл отменять:
`AddFishCommand`, `FeedCommand`, `AddWeedCommand`, `AddDecorationCommand`,
`AddShoalCommand`, `ChangeBiomeCommand` — каждая помнит, что именно сделала
(указатель на созданный объект / предыдущий биом), и умеет откатить именно
это действие через `Scene::Remove*`/повторный `SwitchBiome`. `CommandHistory`
— два стека (`StackAdapter` из Лабы 4) под undo и redo: `Execute` кладёт
команду в undo-стек и очищает redo-стек, `Undo`/`Redo` переносят команду
между стеками, выполняя `Undo()`/`Execute()` по пути (клавиши `Z`/`X`).
`MacroCommand` объединяет несколько команд в одну: `Execute` прогоняет их по
порядку, `Undo` — в обратном порядке (клавиша `P`, пресет из 2 водорослей и
2 декораций, отменяется/повторяется одним нажатием `Z`/`X`).

Все 7 лаб выполнены.

## Доработки после всех 7 лаб

Вне рамок методички — добавлены после того, как все 7 лаб уже были готовы.

- **Еда — биом-осведомлённость + поедание.** `FoodNearbyHandler` реагирует
  только на еду своего биома (`FishContext::food` теперь хранит
  `FoodInfo{position, biomeName}`, а не голые координаты). Новый
  `Scene::HandleEating()` каждый кадр: рыба вплотную к еде своего биома —
  еда исчезает (`Scene::RemoveFood`); хищник вплотную к `Prey`/`Common`
  рыбе любого биома (кроме другого хищника) — рыба исчезает
  (`Scene::RemoveEntity`). Новый `AquaticEntity::AsFish()` (виртуальный
  downcast без RTTI: у `Fish` возвращает `this`, у `Shoal` — `nullptr`)
  исключает из поедания рыб, сгруппированных в стаю, — сознательное
  упрощение, не трогаем `Shoal::members_`.
- **Хищник теперь реально охотится.** Поедание само по себе только
  удаляет жертву при случайном контакте — оно не заставляет хищника
  плыть к ней. `WeedHidingHandler`/`PredatorNearbyHandler` в цепочке
  решений (Лаба 6) оба пропускают хищника (`CanHandle` — `false` для
  `Species::Predator`), так что раньше хищник сразу проваливался в
  `FoodNearbyHandler`/`FlockingHandler` и ловил жертву только по
  совпадению направления. Новый `HuntPreyHandler` (зеркало
  `PredatorNearbyHandler` — не "убегать от хищника", а "плыть к
  ближайшей не-хищной рыбе") встал в цепочку между `PredatorNearbyHandler`
  и `FoodNearbyHandler`: реальная цепочка хищника теперь `HuntPreyHandler`
  → `FoodNearbyHandler` → `FlockingHandler`.
- **Хищник не гоняется за недостижимой добычей.** `HuntPreyHandler` целился
  по всем рыбам аквариума, включая тех, что внутри `Shoal` — а `Shoal`
  съесть нельзя (см. выше). Итог был — бесконечная погоня без результата,
  хищник доходил вплотную и не мог поймать. Новое поле
  `FishContext::huntablePrey` — список только той добычи, которую
  `Scene::HandleEating()` физически способен съесть (строится напрямую по
  `entities_`, минуя `Shoal`); `HuntPreyHandler` целится только по нему.
- **Хищник быстрее своей жертвы.** Раньше все три вида внутри одного биома
  двигались с одной скоростью — убегающая рыба теоретически никогда не
  могла быть поймана. Теперь `Predator` получает ~25% к скорости в каждом
  биоме (`SpeedForSpecies` в `FreshwaterFish`/`ReefFish`/`DeepSeaFish.cpp`).
- **Спрайты вместо фигур.** `src/render/TextureCache.h/.cpp` — кэш
  `sf::Texture` по пути к файлу, грузит каждый файл один раз. Все 12
  продуктов (`Fish`/`Food`/`Weed`/`Decoration` × 3 биома) рисуют
  `sf::Sprite` вместо `CircleShape`/`ConvexShape`/`RectangleShape`; рыбы
  зеркалятся по X при плавании влево, чтобы не выглядели плывущими задом
  наперёд. Плюс фон биома, рисуется первым слоем в `Scene::Draw()`
  (`sprites/{freshwater,reef,deepsea}_background.png`), растягивается под
  текущий размер окна и меняется вместе с биомом (`B`).
- **Плавный поворот вместо дрожания.** Раньше направление рыбы менялось
  на 100% каждый кадр — в плотной стае это приводило к дрожанию на месте
  (расстояние до соседа колеблется туда-сюда у границы разделения).
  `Fish::Update` теперь поворачивает `heading_` только на часть пути за
  кадр (`SteerToward`). Вертикальные края окна (поверхность/дно) стали
  жёсткой границей с "отскоком" направления вместо телепорта — по
  горизонтали телепорт остался как был.
- **Фикс краша при выходе.** Кэш текстур — function-local `static`,
  уничтожался позже, чем `sf::RenderWindow` (уже после выхода из `main()`),
  что роняло приложение при закрытии (`Esc`). `render::ClearCache()`
  теперь вызывается явно в конце `main()`, пока окно ещё живо.
- **Клавиша `U`** — ещё одна демонстрация `MacroCommand`: спавнит 10 еды
  одной командой ("feeding frenzy"), откатывается/повторяется целиком
  через `Z`/`X`.
